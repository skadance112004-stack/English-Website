
Medium Severity Issues
M1. Root typecheck is broken by TypeScript errors and cross-project inclusion
Evidence:
package.json:9 runs react-router typegen && tsc.
tsconfig.json:2-6 includes **/*, which pulls in promo-site.
app/models/lessonModel.ts:169-181 omits TableContent from BlockContent, while table is a BlockType at app/models/lessonModel.ts:35.
app/routes/dashboard.tsx:372-375 reads course.averageProgress, which is not in Course.
promo-site/src/main.tsx:4 imports ./App.tsx, which root tsc rejects without the promo tsconfig options.
Impact: npm run typecheck fails on a fresh root install. CI cannot use the provided validation script as-is.
Suggested fix: Exclude promo-site/** and functions/** from the root app tsconfig or set up project references. Fix the app type errors by adding TableContent and removing/typing averageProgress.
M2. Saved lesson/block docs omit fields requSired by the documented schema
Evidence:
GEMINI.md:55-67 includes lessonId and timestamps for lessons.
GEMINI.md:75-78 includes blockId and timestamps for blocks.
app/models/lessonModel.ts:497-510 omits lessonId and createdAt from saved lesson payloads.
app/models/lessonModel.ts:692-699 omits blockId from saved block docs.
Impact: Clients that expect the documented document shape receive incomplete lesson/block records.
Suggested fix: Write IDs and create timestamps into documents, or update the schema and all consumers to rely on document IDs only.
M3. Exercise and speaking saves contain unawaited duplicate writes
Evidence:
app/route
s/ExerciseCreate.tsx:1384-1396 calls setDoc inside a map without awaiting it and writes a zero-based order.
app/routes/SpeakingCreate.tsx:1102-1107 does the same and spreads full UI meta into the exercise root after an earlier schema-shaped write.
Impact: The UI can show saved and navigate before final writes finish. Late writes can overwrite correct values or add top-level fields that do not belong in the schema.
Suggested fix: Remove duplicate writes or await one schema-shaped update with a consistent order convention.
M4. Generic exercise editor can create malformed speaking exercises
Evidence:
app/routes/ExerciseCreate.tsx:156-157 exposes Speaking in the generic exercise type selector.
app/routes/ExerciseCreate.tsx:1342-1344 saves a passage doc for meta.type === "Speaking".
app/routes/courseCreate.tsx:361-363 otherwise routes speaking exercises to SpeakingCreate.
Impact: A teacher can switch a regular exercise to Speaking and save a speaking exercise with question/passage data instead of conversation lines.
Suggested fix: Remove Speaking from ExerciseCreate or redirect to SpeakingCreate when selected.
M5. Course and section writes embed UI-only arrays outside the documented schema
Evidence:
app/models/courseModel.ts:168-177 writes items inside section docs.
app/routes/SpeakingCreate.tsx:1114 writes sections: us to the course root through updateCourse.
GEMINI.md:3-34 and 41-49 do not include sections on courses or items on sections.
Impact: Course structure is duplicated across course, section, lesson, and exercise documents, making drift likely.
Suggested fix: Use one canonical ordering source, or explicitly update the schema and consumers to support embedded items.
M6. Course deletion leaves subcollections and storage behind
Evidence:
app/models/courseModel.ts:228-230 deletes only courses/{courseId} and users/{teacherId}/courses/{courseId}.
GEMINI.md defines nested sections, lessons/blocks, exercises/questions/content/lines, and reviews.
Impact: Deleting a course leaves orphaned Firestore data and likely storage files.
Suggested fix: Use an Admin callable or backend job to verify ownership and recursively delete Firestore and Storage data.
M7. Account deletion leaves profile, course, and storage data behind
Evidence:
app/routes/settings.tsx:170-174 calls deleteUser(user) and navigates away.
No user document, stats, courses, or storage files are deleted.
Impact: Deleting an account leaves orphaned teacher and course data.
Suggested fix: Move account deletion into a backend callable that recursively deletes owned data, then deletes the Auth user.
M8. Settings email field is editable but never saved
Evidence:
app/routes/settings.tsx:63 stores editable email state.
app/routes/settings.tsx:338 renders an editable email input.
app/routes/settings.tsx:111-116 saves name, phone, bio, and notifications only.
Impact: Teachers can edit email, click Save, and see success while Auth and Firestore email remain unchanged.
Suggested fix: Make email read-only or implement reauthentication, updateEmail, and Firestore email update.
M9. Course management filters hide data by default and several controls do nothing
Evidence:
app/routes/CoursesManagement.tsx:201-204 defaults level to B2, category to Business English, max students to 500, and date filter to 30 days.
app/routes/CoursesManagement.tsx:247-252 filters only search, status, level, and students.
app/routes/CoursesManagement.tsx:372-377 renders an Apply button that has no handler.
Impact: Teachers may see an empty course list even when courses exist. Category, date, sort, and Apply controls mislead users.
Suggested fix: Default filters to neutral values and implement category/date/sort/apply behavior, or remove inactive controls.
M10. Dashboard uses missing averageProgress field
Evidence:
app/routes/dashboard.tsx:372-375 reads course.averageProgress.
app/models/courseModel.ts:50-86 does not define that property.
tsconfig.json:25 enables strict type checking.
Impact: Typecheck fails, and dashboard progress always falls back to 0% unless untyped data happens to include the field.
Suggested fix: Add and populate averageProgress from enrollment/progress data, or remove/replace the progress UI.
M11. TTS voice catalog differs between client and backend
Evidence:
app/service/ttsService.ts:21 exposes en-US-TonyNeural.
functions/src/generateTTSAudio.ts:11-22 backend AZURE_VOICES omits Tony.
functions/src/generateTTSAudio.ts:147 rejects unknown voices.
Impact: Selecting Tony in the UI causes TTS generation to fail for that line.
Suggested fix: Share a single voice catalog between client and backend or update both lists together.
M12. TTS SSML interpolates unescaped user/AI text
Evidence:
app/service/ttsService.ts:78-83 sends raw trimmed line text.
functions/src/generateTTSAudio.ts:80-89 inserts the text directly into SSML XML.
Impact: Line text containing &, <, >, or SSML-like tags can break Azure TTS or inject unintended SSML.
Suggested fix: XML-escape line text before constructing SSML or use a safe SSML builder.
M13. TTS can create partial line documents
Evidence:
functions/src/generateTTSAudio.ts:195-200 uses set(..., { merge: true }) even if the line document has not been saved yet.
GEMINI.md:198-207 requires complete line fields including lineId, order, speaker, text, audioUrl, and isUserLine.
Impact: Running TTS before saving the speaking exercise can leave partial lines/{lineId} docs.
Suggested fix: Require existing line docs before writing audio or save complete line schema before generating TTS.
M14. Firebase client config is hardcoded
Evidence:
app/firebase/firebase.ts:7-15 hardcodes API key, project ID, app ID, bucket, and measurement ID.
Impact: Every build points at the same Firebase project, making staging/dev separation and safe deployments error-prone. The API key is public config, but the environment binding is still hardcoded.
Suggested fix: Load public Firebase config from documented environment variables per deployment environment.
M15. Data Connect schema is unrelated placeholder content
